# Market Pulse frontend

Next.js (App Router) + TypeScript + Tailwind CSS. This is the presentation layer only: all data
comes from the FastAPI backend, which the Next.js server calls on the browser's behalf (ADR-0004).

Requires Node.js 22.18 or later (CI uses Node 24): `pnpm test` runs the TypeScript test files
directly with Node's built-in type stripping. pnpm 12 is pinned in `package.json`
(`packageManager`).

```bash
pnpm install         # install locked dependencies
pnpm dev             # http://localhost:3000

pnpm lint            # ESLint (zero warnings allowed)
pnpm typecheck       # TypeScript strict type check
pnpm test            # unit tests (node --test, src/**/*.test.ts)
pnpm build           # production build

pnpm api:types       # regenerate src/lib/api-schema.ts from ../backend/openapi.json
pnpm api:check       # fail if src/lib/api-schema.ts is stale
pnpm notices         # regenerate THIRD_PARTY_NOTICES.md and the /notices page data
pnpm notices:check   # fail if either is stale
```

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `MARKETPULSE_API_URL` | `http://localhost:8000` | Backend URL, server-side only |

Next.js reads `.env*` files from this directory (`frontend/`), not the repository root. To
override the default, create `frontend/.env.local` (gitignored).

In development, open the app at `http://localhost:<port>`: `next dev` blocks its development
resources (hot reload) for other host names such as `127.0.0.1` unless they are listed in
`allowedDevOrigins`.

## API types

Response types are generated, not written by hand:

1. The backend writes its OpenAPI schema to `backend/openapi.json`
   (`uv run marketpulse openapi --output openapi.json`; no database or settings file is read).
   `backend/tests/test_openapi_contract.py` fails if that file is stale.
2. `pnpm api:types` runs [openapi-typescript](https://openapi-ts.dev/) (a development
   dependency, pinned) to produce `src/lib/api-schema.ts`. `pnpm api:check` (in CI) fails if it
   is stale.
3. `src/lib/api.ts` exposes readable aliases (`SeriesSummary`, `CalculatedMetric`, ...) of the
   generated types. Only frontend-only shapes (`ApiResult`, the chart route's `ChartHistory`) are
   written by hand.

Market values are decimal **strings** in the schema and in the generated types; they are never
parsed into floats except to position chart points. Nullable fields are `T | null`; error bodies
are `ErrorResponse` (404, 503) and `ValidationErrorResponse` (422).

## Conventions

- Design tokens live in `src/app/globals.css` (`bg-panel`, `text-muted`, `text-up`, `text-down`,
  `text-status-*`). Use semantic tokens, not raw colors. The three text levels (`text-fg`,
  `text-muted`, `text-faint`) all meet WCAG AA contrast (4.5:1) on every surface token.
- Shared primitives live in `src/components/ui/` (`Badge`, `Button`), following the shadcn/ui
  file convention. shadcn/ui (ADR-0004) will be added there when a component needs a Radix
  primitive (dialog, dropdown, tabs, command menu); the current views need none, so no UI
  library is installed yet.
- Data that must be fresh on every request is fetched in server components wrapped in
  `<Suspense>`, with `connection()` so it is never prerendered (Next.js 16 Cache Components).
- Every data panel shows its source, period, and freshness; calculated values are labeled
  "Calculated" and synthetic fixtures "Synthetic" (and are refused by production builds).
- Modules that are not operational are labeled "Planned" or "On hold" in the navigation and
  page header, in text.
- See `AGENTS.md`: this Next.js version differs from older documentation. Check
  `node_modules/next/dist/docs/` before using unfamiliar APIs.

## Accessibility

- A "Skip to content" link is the first focusable element; keyboard focus always shows a 2 px
  accent outline (`:focus-visible`), and motion is reduced when the system asks for it.
- One `h1` per page (the page header), `h2` per section, `h3` per card or chart; sections are
  labelled regions.
- Information is never carried by color or by a hover tooltip (`title`) alone: badges have text,
  unavailable chart ranges stay focusable with their reason announced, and directions use
  arrows plus signed values.
- Each chart is described in text (range, latest, lowest and highest values with their periods,
  gaps), announced again when the range changes. Synthetic lines are also dashed and
  watermarked.

## Third-party notices

`THIRD_PARTY_NOTICES.md` (also served at `/notices` and linked from every page footer and chart)
is generated by `scripts/third-party-notices.mjs` from installed package metadata and license
files. Files that the npm packages do not include (the Lightweight Charts NOTICE, the
fancy-canvas license, the Geist font license) are kept verbatim in `third-party/upstream/`, with
their sources. Platform-specific binary packages (the Next.js compiler and sharp, of which each
machine installs only its own variant) are listed by family from the lockfile, so the output is
the same on Windows, macOS, and Linux; their declared licenses are checked against the installed
variants on every run. The TradingView attribution on every chart must remain.
